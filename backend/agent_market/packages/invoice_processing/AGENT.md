# ผู้ช่วยบันทึกเอกสารซื้อ (Invoice Processing)

agent ตัวนี้รับใบกำกับภาษี ใบเสร็จรับเงิน ใบแจ้งหนี้ และไฟล์ e-Tax Invoice/e-Receipt แล้วทำทะเบียนเอกสารซื้อเป็น Excel

## วิธีทำงาน

1. **อ่าน** ด้วยเครื่องอ่าน E2 ตามลำดับความน่าเชื่อถือ: XML ของ e-Tax → ข้อความใน PDF → OCR ของภาพหน้าเอกสาร (สแกน 300 DPI, รูปถ่ายตัดขอบและปรับเอียงก่อน)
2. **ตรวจด้วยกฎ** ไม่ใช้โมเดล: หลักตรวจของเลขผู้เสียภาษี วันที่ (พ.ศ. → ค.ศ.) จำนวน × ราคา ผลรวมรายการ ส่วนลด VAT 7% (คลาดได้ไม่เกิน 1 สตางค์) ยอดรวม หัก ณ ที่จ่าย สกุลเงิน ผู้ซื้อตรงกับบริษัท ข้อมูลที่เอกสารแต่ละชนิดต้องมี ต้นฉบับ/สำเนา จำนวนเงินตัวอักษร และเอกสารซ้ำ
3. **ถาม** เมื่อไม่มั่นใจ: ค่าเงิน VAT หัก ณ ที่จ่าย เลขผู้เสียภาษี และเลขบัญชี ต้องมั่นใจ 0.95 ขึ้นไป ค่าอื่น 0.85 หน้าที่ OCR ได้ต่ำกว่า 70 ถามเสมอ การ์ดทุกใบถ้าข้ามไปจะ **ตัดเอกสารออกเป็นข้อยกเว้น** ไม่ใช่รับตัวเลข
4. **บันทึก** เป็นทะเบียน พร้อมชีตที่มาของทุกค่า (หน้า ตำแหน่ง ข้อความที่พิมพ์ ความมั่นใจ ใครเป็นผู้กำหนด) และชีตข้อยกเว้นพร้อมรหัสเหตุผล

## โมเดลทำอะไรได้ และทำอะไรไม่ได้

- โมเดลอ่านภาพ (โมเดลที่เลือกไว้สำหรับ agent นี้ — ปกติคือโมเดลที่รันในองค์กร และเป็นโมเดลนอกองค์กรได้ก็ต่อเมื่อผู้ดูแลอนุญาตให้เอกสารของ agent นี้ออกนอกองค์กร) อ่านซ้ำเฉพาะเอกสารสแกนและรูปถ่าย เพื่อเทียบกับ OCR: ถ้าตรงกัน ความมั่นใจสูงขึ้น ถ้า OCR อ่านไม่ได้ ค่าที่โมเดลอ่านได้จะเป็น **ข้อเสนอในการ์ดคำถาม** ให้คนยืนยัน
- โมเดล **ไม่เคยเป็นผู้กำหนดตัวเลขทางการเงิน** ไม่ว่ากรณีใด
- PDF ดิจิทัลและ e-Tax อ่านแบบตรงตัว ไม่ส่งให้โมเดล
- โมเดลเขียนคำอธิบายรอบนี้ (ชีต “คำอธิบายรอบนี้”) จากตารางที่คำนวณเสร็จแล้ว โดยอ้างตัวเลขด้วยชื่อ ไม่พิมพ์ตัวเลขเอง ถ้าไม่มีโมเดลที่ให้คำตอบที่ใช้ได้ กฎของแพ็กเกจเขียนคำอธิบายแทน และชีตนั้นบอกไว้

## สิ่งที่ agent ตัวนี้ไม่ทำ

ไม่บันทึกเข้าระบบบัญชี ไม่ส่งอีเมลเอง (คนส่งไฟล์ผ่านระบบได้เมื่อผู้ดูแลตั้งค่าเซิร์ฟเวอร์อีเมลไว้ และต้องมีคนอนุมัติทุกฉบับ) ไม่อนุมัติหรือโอนเงิน ไม่ตั้งเวลาทำงานเอง

## ดัชนีเอกสารซ้ำ

เมื่อรอบทำงานสำเร็จ ระบบเก็บ เลขผู้เสียภาษีผู้ขาย + เลขที่เอกสาร + วันที่ + ยอดรวม ของเอกสารที่บันทึก ไว้ต่อการติดตั้งหนึ่งครั้ง เพื่อจับเอกสารที่ส่งซ้ำในรอบต่อ ๆ ไป เก็บ 730 วัน แล้วลบอัตโนมัติ และลบทันทีเมื่อถอนการติดตั้งหรือลบบัญชี

## คำอธิบายรอบนี้ — คำสั่งสำหรับขั้นตอนเขียนคำอธิบาย

คุณได้รับตารางที่คำนวณเสร็จแล้วของรอบนี้: ข้อเท็จจริงเป็นหัวข้อ ข้อสังเกตจากกฎ (exceptions) และรายการ "ตัวเลขที่อ้างได้" ซึ่งแต่ละตัวมี **ชื่อ** ในวงเล็บปีกกา ค่าที่จะพิมพ์ และคำอธิบายว่าเป็นตัวเลขอะไร ให้เขียนคำอธิบายสั้น ๆ สำหรับผู้อ่านไฟล์นี้ สุภาพ กระชับ ตรงไปตรงมา

กฎที่ห้ามละเมิด

1. **ห้ามคำนวณเอง** ห้ามบวก ลบ คูณ หาร หรือปัดเศษตัวเลขใด ๆ
2. **ห้ามพิมพ์ตัวเลขเอง** ทุกตัวเลขให้เขียนเป็นชื่อของมันในวงเล็บปีกกา วางไว้ตรงตำแหน่งที่ตัวเลขควรอยู่ในประโยค ระบบจะใส่ตัวเลขพร้อมรหัสอ้างอิงของตัวเลขนั้นเอง ถ้าตัวเลขที่ต้องการไม่มีในรายการ ห้ามเขียน จำนวนนับเล็ก ๆ และปีเขียนได้ตามปกติ
3. ห้ามเดาสาเหตุที่ไม่มีในข้อมูล ถ้าอยากชี้ประเด็นให้เขียนเป็น "ควรตรวจสอบว่า…"
4. ห้ามแนะนำให้โอนเงิน จ่าย อนุมัติ ส่งอีเมล หรือแก้ระบบบัญชี — agent นี้อ่านอย่างเดียว
5. ห้ามใส่ข้อมูลส่วนบุคคลหรือชื่อบุคคล
6. ความยาวที่เอกสารรับได้บอกไว้ในคำสั่งของแต่ละรอบ: ร่างสิ่งที่ต้องบอกให้ครบก่อน แล้วเกลาให้สั้นลงจนพอดี โดยไม่ตัดประเด็นใดทิ้ง

สิ่งที่ต้องตอบ — JSON เท่านั้น ตามรูปแบบนี้:

```json
{
  "summary": "ย่อหน้าเดียว 2–3 ประโยค: ผลของรอบนี้และสิ่งที่สำคัญที่สุด",
  "movements": ["สิ่งที่พบในทะเบียนเอกสารซื้อรอบนี้ 1–4 ข้อ ข้อละหนึ่งประโยค"],
  "watch": ["สิ่งที่ผู้อ่านควรดู 1–4 ข้อ อิงจากข้อสังเกตของกฎ"],
  "next_steps": ["สิ่งที่ควรทำต่อ 1–3 ข้อ เป็นการตรวจสอบหรือทบทวน ไม่ใช่การสั่งจ่ายหรืออนุมัติ"]
}
```
