# ผู้ช่วยตรวจการเบิกค่าใช้จ่าย (Expense Audit)

agent ตัวนี้รับไฟล์รายการเบิกค่าใช้จ่าย (Excel หรือ CSV หนึ่งแถวต่อหนึ่งรายการ) พร้อมใบเสร็จ แล้วตรวจทุกรายการตามตารางนโยบายการเบิกของบริษัท ได้ผลตรวจเป็น Excel

## เส้นแบ่ง: กฎให้ข้อเท็จจริง คนเป็นผู้ตัดสิน

**กฎ (ตรวจด้วยสคริปต์ ไม่ใช้โมเดล) ให้ข้อเท็จจริง** ว่าแต่ละรายการ ผ่าน / ไม่ผ่าน / ไม่เกี่ยว พร้อมหลักฐาน:

| กฎ | ไม่ผ่านเมื่อ | รหัสเหตุผล |
|---|---|---|
| วงเงินต่อครั้ง | ยอดเบิกเกินวงเงินต่อครั้งของหมวดในตาราง | `over_claim_limit` |
| วงเงินต่อคนต่อเดือน | ยอดสะสมของพนักงานคนเดียว หมวดเดียว เดือนเดียว (เรียงตามวันที่) เกินวงเงิน — รายการที่ทำให้เกินและรายการหลังจากนั้น **นับยอดที่เบิก** เพราะตรวจก่อนมีใครตัดสินข้อยกเว้น | `over_period_limit` |
| ใบเสร็จ | ยอดเกินเกณฑ์ที่ต้องมีใบเสร็จ แต่ไม่มีใบเสร็จ (หรืออ้างถึงไฟล์ที่ไม่ได้ส่งมา) | `missing_receipt` |
| ยอดตรงใบเสร็จ | ยอดรวมในใบเสร็จ (อ่านด้วย E2) ไม่เท่ากับยอดที่เบิก / ยืนยันยอดในใบเสร็จไม่ได้ | `receipt_amount_mismatch` / `receipt_unconfirmed` |
| เบิกซ้ำ | พนักงาน ร้าน วันที่ และยอดเดียวกัน หรือใบเสร็จไฟล์เดียวกัน (ไบต์ตรงกัน) ในสองรายการ หรือใบเสร็จที่เคยเบิกในรอบก่อน | `duplicate_claim` |
| แยกบิล | พนักงานคนเดียว ร้านเดียว วันเดียว หลายรายการ แต่ละรายการต่ำกว่าวงเงินอนุมัติ แต่รวมกันเกิน (รายการที่ซ้ำไม่นับ เพราะเป็นการซื้อครั้งเดียวกัน) | `split_purchase` |
| ร้านต้องห้าม | ชื่อร้านในไฟล์ หรือชื่อผู้ขายในใบเสร็จ มีคำในรายชื่อร้านต้องห้าม | `prohibited_merchant` |
| เอกสารขอคืน VAT | ขอคืนภาษีซื้อ แต่เอกสารไม่ใช่ใบกำกับภาษีเต็มรูปที่ออกในนามบริษัท | `vat_claim_without_full_tax_invoice` |
| หัก ณ ที่จ่าย | หมวดที่ตารางกำหนดอัตราหัก ณ ที่จ่าย ยอดถึงเกณฑ์ แต่ไม่ได้หัก / หักไม่ตรง | `wht_missing` / `wht_mismatch` |
| วัตถุประสงค์ (หมวดที่ต้องระบุ) | หมวดที่ตารางกำหนดว่าต้องระบุวัตถุประสงค์ แต่ไม่ได้เขียนรายละเอียดเลย | `missing_purpose` |
| หมวด / ข้อมูลในแถว | หมวดไม่อยู่ในตาราง / อ่านวันที่ จำนวนเงิน หรือพนักงานไม่ได้ | `unknown_category` / `claim_row_unreadable` |

กฎที่ไม่ผ่านกลายเป็น **ข้อยกเว้นรอคนตัดสิน** (run exception) พร้อมหลักฐาน (ไฟล์ แถว เซลล์ ใบเสร็จ หน้า ข้อความที่พิมพ์ ตำแหน่งในตารางนโยบาย) สิ่งที่เสนอให้ทำ และทางเลือกของผู้ตัดสิน เช่น อนุมัติเป็นกรณียกเว้น / ถามพนักงาน / ไม่เบิกจ่ายรายการนี้ — ไม่มีทางเลือกใดถูกเลือกไว้ให้

**เรื่องที่ต้องใช้วิจารณญาณ ถามคนผ่านการ์ด** กฎเห็นได้แค่สิ่งที่กระตุ้นให้ถาม ส่วนการตัดสินเป็นของคน:

| สิ่งที่กระตุ้น | การ์ด | รหัสเหตุผล |
|---|---|---|
| วันที่เป็นวันเสาร์–อาทิตย์หรือวันหยุด (นโยบาย `weekend_holiday: "flag"`) | เป็นงานของบริษัทหรือไม่ | `weekend_or_holiday` |
| รายละเอียดว่าง เป็นแค่ชื่อหมวด (เช่น “ค่าอาหาร” ในหมวดค่าอาหาร) หรือเป็นคำกว้าง ๆ | วัตถุประสงค์ทางธุรกิจชัดพอหรือไม่ (พิมพ์วัตถุประสงค์ที่ได้จากพนักงานได้) | `vague_purpose` |

คำตอบในการ์ด: “รับได้” บันทึกไว้ว่าคนยืนยันแล้ว · “ให้ถามพนักงาน” และ “ส่งให้ผู้อนุมัติตัดสิน” เป็นข้อยกเว้นรอคนตัดสิน · **ข้ามการ์ด = ส่งให้ผู้อนุมัติตัดสิน** ไม่ใช่ผ่าน รายการที่ไม่ผ่านกฎอยู่แล้ว (ไปถึงคนอยู่แล้ว) จะไม่ถูกถามซ้ำ แต่สิ่งที่ต้องพิจารณาจะติดไปกับข้อยกเว้นนั้น ถ้านโยบายตั้ง `weekend_holiday: "exception"` วันหยุดเป็นข้อยกเว้นแทนการ์ด

ผลของแต่ละรายการมีสามแบบเท่านั้น: **ผ่าน** · **ข้อยกเว้น** (กฎไม่ผ่าน คนตัดสิน) · **ต้องใช้วิจารณญาณ** (การ์ด) — **ไม่มีการปฏิเสธอัตโนมัติ** ไม่มีรายการใดถูกตัด ลด หรือเปลี่ยนยอดโดยระบบ

## ที่มาของวงเงิน

- **ตารางนโยบายที่ตั้งไว้ใน agent (ค่า `policy`) เป็นที่มาเดียวของวงเงิน** เกณฑ์ อัตรา และรายชื่อร้านต้องห้าม ถ้ายังไม่มีตารางหรือตารางไม่ครบ agent จะถามและไม่ตรวจ ไม่เดาวงเงินเอง ไฟล์นโยบาย Excel อ่านเข้าตารางได้ตอนติดตั้ง (`policy_from_xlsx`) โดยบอกค่าที่ไฟล์ไม่ได้ระบุให้เจ้าของกรอก ในรอบทำงานไม่อ่านไฟล์นโยบาย
- **เอกสารระเบียบ (.docx / .txt) เป็นบริบทเท่านั้น** ข้อความถูกยกมาข้างข้อยกเว้นที่เกี่ยวข้อง ถ้าในเอกสารมีตัวเลขต่างจากตาราง ระบบบอกว่าต่างและใช้ตาราง ตัวเลขในเอกสารไม่เคยเป็นวงเงิน แม้ตารางไม่ได้กำหนดวงเงินนั้นเลยก็ตาม
- ปฏิทินวันหยุด: ตรวจวันหยุดนักขัตฤกษ์เฉพาะเมื่อมีปฏิทินวันหยุดของบริษัทที่คนยืนยันแล้ว (ค่า `holidays`) ถ้าไม่มี จะไม่ใช้ปฏิทินวันหยุดราชการแทนเอง ตรวจเฉพาะวันเสาร์–อาทิตย์ และบอกไว้ในผลตรวจว่ายังไม่ได้ตรวจวันหยุดนักขัตฤกษ์

## โมเดลทำอะไรได้ และทำอะไรไม่ได้

- ใบเสร็จอ่านด้วยเครื่องอ่าน E2: XML ของ e-Tax → ข้อความใน PDF → OCR ของภาพ ใช้ยอดรวมเทียบกับยอดที่เบิก และชนิดเอกสารเมื่อขอคืนภาษีซื้อ ถามเฉพาะเมื่อไม่มั่นใจเรื่องเหล่านี้
- โมเดลอ่านภาพ (qwen3.8-27b-fp8 ที่รันในองค์กร) อ่านซ้ำเฉพาะใบเสร็จที่เป็นสแกนหรือรูปถ่าย ค่าที่อ่านได้เป็น **ข้อเสนอในการ์ดคำถาม** ให้คนยืนยันเท่านั้น
- โมเดล **ไม่เป็นผู้กำหนดตัวเลขใด** และไม่ตัดสินว่ารายการใดผ่านหรือไม่ผ่าน คำสรุปเขียนจากกฎ

## สิ่งที่ agent ตัวนี้ไม่ทำ

ไม่อนุมัติหรือปฏิเสธการเบิก ไม่บันทึกเข้าระบบบัญชี ไม่ส่งอีเมลเอง (คนส่งไฟล์ผ่านระบบได้เมื่อผู้ดูแลตั้งค่าเซิร์ฟเวอร์อีเมลไว้ และต้องมีคนอนุมัติทุกฉบับ) ไม่โอนเงิน ไม่ตั้งเวลาทำงานเอง

## ดัชนีใบเสร็จที่เคยเบิก

เมื่อรอบทำงานสำเร็จ ระบบเก็บลายนิ้วมือ (sha256) ของใบเสร็จที่ถูกอ้างถึงในรายการเบิก และค่าที่อ่านได้ (เลขผู้เสียภาษีผู้ขาย เลขที่ วันที่ ยอดรวม) ไว้ต่อการติดตั้งหนึ่งครั้ง เพื่อจับใบเสร็จเดิมที่ถูกนำมาเบิกซ้ำในรอบต่อ ๆ ไป เก็บ 730 วัน แล้วลบอัตโนมัติ และลบทันทีเมื่อถอนการติดตั้งหรือลบบัญชี
