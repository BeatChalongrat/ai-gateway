# Known-failing backend tests — the gate compares NAMES, never a count.
#
# Why this file exists: the release gate used to be "the lane must show
# exactly N failures". A suite this size does not produce a stable N —
# three consecutive runs of the same tree gave 21, 22 and 23 failures
# with a different extra member each time, and every drifting member
# passed when run on its own. A count cannot tell "the same old
# breakage" apart from "something new broke", so the gate reads the list
# below: a name that is not here turns the gate red, and a different
# total with the same names is green.
#
# ── FIX57: regenerated, and the ordering it is valid for is now fixed ──
#
# The list above was built against a RANDOM order. pytest-randomly seeds
# itself from the clock, so every lane reshuffled the suite and a
# different set of order-dependent tests fell over — two lanes on one
# unchanged tree disagreed about which failures were "new" (8 names one
# way, 15 the other, every one of them passing in isolation). A ledger of
# names cannot survive that: it is a statement about one ordering.
#
# The seed is pinned in pyproject.toml (`--randomly-seed=0`). The shuffle
# stays — it is the only reason this suite's shared-state bugs ever
# surface — but it is the SAME shuffle every run, so this list means
# something. Changing that seed reshuffles the suite and invalidates this
# file; regenerate it in the same commit.
#
# Four drifters were fixed rather than recorded here, because each had an
# actual cause: two cookie tests whose "tampering" decoded to the same
# base64 bytes about one run in sixteen; a routing-settings cache read
# before its session check; a model-registry reload emptying the seeded
# catalogue for every later test; and Redis health markers surviving into
# the SSE tests. See the FIX57 commits.
#
# THE ONE COMMAND:
#   docker exec -e APP_ENV=test ai-gateway-backend-1 \
#     sh -c "cd /app && python -m pytest -m 'not integration' -q"
#   python backend/scripts/check_known_failing.py <that output>
#
# Rules for this file:
#   * every entry carries a reason and the date it was added;
#   * it must shrink over time — it is a ledger of known breakage, not
#     a place to hide new failures;
#   * NEVER add a name to make the gate pass. If a change breaks a
#     test, fix the change.
#
# Format: <test id>  # <YYYY-MM-DD> <reason>
# Blank lines and lines starting with # are ignored.
#
# Verified 2026-09-05: three consecutive lanes on one tree produced these
# 24 names and no others, byte-identical.
