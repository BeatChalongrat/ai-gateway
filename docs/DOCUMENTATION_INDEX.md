## How to interpret the inventory

The source review corrected stale active descriptions: WPF versus Electron,
Node versus Go MCP gateway, migration heads, provider inventory, admin auth,
Redis/retention/monitoring state and Office transfer/edit behavior.

Operational procedures are retained without pretending they were executed.
Historical observations retain their dates. Runtime AGENT/prompt files are
application inputs, so a documentation refresh does not rewrite their model
instructions or mark package acceptance complete.

The inventory covers every baseline Markdown path, but **does not certify every
historical statement or re-run every operational procedure**. The running stack,
tenant settings, remote CI runner and certificate inventory were not re-audited.
The rollback book is generated by its own tool; the October snapshot is not
relabelled as a November deployment. Source changes were not deployed.

## Maintenance rules

Update the current owning document when a contract changes. Link to it from
summaries instead of duplicating full specifications. Keep test results attached
to a date, command and scope; a structural Office test is not visual acceptance.
Re-run repository pointer checks with new maintained files included in the
proposed change set. Do not add ignored working reports to satisfy a link.

Public comparison sources and remaining Claude/Cowork gaps are centralized in
[Office workflows](OFFICE_WORKFLOWS.md). This index itself is the inventory owner.
